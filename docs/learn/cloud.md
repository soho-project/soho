# 云服务与微服务协作

参考文档：

- <https://sca.aliyun.com/docs/2021/overview/version-explain/>

## 背景

微服务架构可以解决大型系统拆分问题，但在实践中也会带来一系列额外成本，例如：

- 服务注册与发现
- 服务间通信
- 服务配置管理
- 服务监控与追踪
- 服务网关
- 限流、熔断、降级与容错

如果团队尚未建立统一规范，微服务化通常会明显拉低开发效率。

## 当前项目建议

本项目推荐采用“单体优先、接口隔离、后续可拆”的开发方式：

- 业务开发阶段先按模块拆分代码，而不是一开始就拆分部署。
- 业务模块之间不要直接依赖对方实现，统一通过 API 模块或桥接层调用。
- 当后续需要独立部署时，可在现有模块边界基础上逐步拆分。

## 设计目标

这种方式的主要目标是：

- 在项目早期保持较低开发成本
- 降低团队对完整微服务体系的学习成本
- 避免业务模块之间出现强耦合
- 为后续服务拆分预留边界
